## 2. Where pending work is recorded

**`docs/BACKLOG.md`** is the single index of what is not done, each item with an id, an owner
(Pranav or agent), the document holding its detail, and a GitHub issue number once one exists. Detail
stays in the original documents (`capranav_com_revamped/AGENT-HANDOFF.md` §4, the second-edition register,
the Must Practice skill); the backlog only points to them. When you finish or discover something,
update the backlog in the same commit.

**GitHub issues** are generated from the backlog, not written by hand: `python tools/backlog_to_issues.py`
is a dry-run that lists the issue each row would become (labels `priority:*`, `owner:*`, `area:*`); with
`--execute` it creates them and records the numbers in `docs/backlog-issues.json`. **Do not run it with
`--execute` until Pranav has decided where issues live (BL-R02): the repo is public, so issues would be too.**

## 4. How the repo is worked (read before you commit or push)

- **Concurrent sessions.** Another session pushes to `origin/main` while you work, so a push is often
  rejected. Recipe that has worked every time:
  1. `find .git/refs -name desktop.ini -delete` (Google Drive drops `desktop.ini` files into `.git/refs`
     and they break `git fetch` with "bad object refs/codex/desktop.ini"; they are not real refs).
  2. `git fetch origin main`, then `git log HEAD..origin/main` and compare changed files.
  3. `git merge origin/main`. The usual conflict is `_claude/memory/project_log.md` (both sides add
     entries at the top): keep **both** sets of entries, newest first, no markers left.
  4. Regenerate `_claude/artifacts/file-index.md` (`python tools/file_index.py`, takes about 2 minutes:
     run it in the background), commit, push. Never force-push.
- **A background job commits changes as "auto: N file(s) updated"** every few minutes, including other
  sessions' unfinished files. Its owner and schedule are not documented in the repo (see backlog BL-R03).
  Do not assume a clean tree means your work is pushed: check `git status -sb` and `git fetch`.
- **The repo is public on GitHub** although the EC operating guide says private (see backlog BL-R01).
  Never put secrets, personal data or anything you would not publish in a file here.

## 5. Verify your work

- `python tools/health_check.py` then `python tools/file_index.py` after any structural change (add,
  move, rename, delete). Each takes one to three minutes; run them in the background.
- Must Practice or capranav.com changes: `cd capranav_com_revamped`, build, `npx wrangler deploy`,
  then `python tools/verify_must_practice_live.py` (a real browser check, needs Playwright and Edge;
  plain `curl` gets a 403 on data files by design) and `python tools/qa_smoke.py --browser`.
- Look at a screenshot of any layout change; reading the code is not enough.

## 6. Tool gotchas on this Windows machine

- Shell is Git Bash. Long Python snippets with quotes inside `python - <<'EOF'` often break: write the
  script to a file and run it.
- `pdftoppm` is not installed, so a PDF cannot be rendered by the Read tool. PyMuPDF is in the repo
  `.venv`: `fitz` (`import fitz; page.get_pixmap(dpi=110).save("x.png")`), then read the PNG.
- Python needs `PYTHONIOENCODING=utf-8` to print rupee signs.
- `ls` and `git status` show Google Drive `desktop.ini` noise; ignore it.
