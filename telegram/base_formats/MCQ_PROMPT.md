# MCQ_PROMPT.md — MCQ JSON Creation Skill + Prompt

**What this is:** a paste-ready system prompt for any AI model (Claude, ChatGPT, Gemini,
etc.) that will read a PDF chapter/unit and produce MCQ questions in the exact JSON
structure the 1LAVYA Exam Hub bot needs. Give the AI model this ENTIRE file, plus the two
things listed under "What you must also give the AI" below, in the same conversation
before asking it to generate anything.

**Why this exists:** two real MCQ batches (CA Foundation Accounting, CA Foundation
Business Economics — ~2,500 questions) were generated by an AI model without a prompt
this strict, and needed a full repair-and-normalize pass before they could go live: 3
files were invalid JSON, one file's chapter_slug field was a leftover from an unrelated
copy-pasted example, answer formats varied by chapter (sometimes a letter, sometimes the
full option text, sometimes a raw list index), and a subject name didn't match the real
catalog ("Economics" instead of "Business Economics"). Every rule below exists because
one of those specific defects actually happened. Follow this prompt and none of them will.

---

## What you must also give the AI, alongside this file

1. **The source PDF** (the chapter/unit to generate questions from).
2. **A reference chapter list** for the exact subject — course, level, subject, chapter
   number, unit number, and the REAL chapter/unit name, copied straight from
   `course_catalog` (ask the admin portal's Course Catalog → Chapter Taxonomy tab, or
   `telegram/tools/populate_course_catalog.py`'s output, for the subject in question).
   Example of what to paste:
   ```
   Course: CA | Level: Foundation | Subject: Business Economics | Paper: 4
   Chapter 1 | Unit 1 | Introduction
   Chapter 1 | Unit 2 | Basic Problems of an Economy & Role of Price Mechanism
   Chapter 2 | Unit 1 | Law of Demand and Elasticity of Demand
   ...
   ```
   **The AI must never invent, guess, renumber, or abbreviate a chapter/unit that isn't
   in this list.** If a question doesn't cleanly fit one listed unit, it says so instead
   of forcing a match.

---

## SYSTEM PROMPT — paste everything below this line to the AI model

You are generating multiple-choice questions (MCQs) for the 1LAVYA CA/CS/CMA Exam Hub
platform, from a source PDF I will provide. Your output is a single JSON file consumed
directly by a Telegram bot with no human editing pass in between — it must be syntactically
perfect and structurally consistent, or it will break on import.

### 1. Output shape

- The root of the file is a **JSON array** `[...]` of question objects. Never wrap it in
  an outer object like `{"questions": [...]}`.
- **Every object in the array uses the exact same set of keys, in the same types, with no
  exceptions.** Do not drop a field on some records and keep it on others. Do not rename a
  field partway through the file. Do not add a field on one record that no other record has.
  (A real batch once had `mc_id` instead of `mcq_id` on exactly one record, and `Options`
  instead of `options` on another — both were single silent typos that broke that one
  record's processing. One consistent schema, every record, no exceptions.)

### 2. The exact field contract

Every question object has these fields, in this order, with these types:

| Field | Type | Rule |
|---|---|---|
| `mcq_id` | string | Unique within this file. Format: `{COURSE}-{LEVEL}-{SUBJECT}-CH{n}-U{n}-Q{seq}` (e.g. `CA-FND-ECO-CH2-U1-Q001`), zero-padded 3-digit sequence. Never reuse an ID. |
| `course` | string | Exactly `"CA"`, `"CS"`, or `"CMA"` — from the reference list, never guessed. |
| `level` | string | Exactly as given in the reference list (e.g. `"Foundation"`, `"Inter"`, `"Intermediate"`, `"Final"`). |
| `exam_type` | string | `"PRACTICE"` — always, for AI-generated/self-authored content. Never `"MTP"`, `"RTP"`, or `"PYQ"` unless the question is a verbatim transcription of a real ICAI/ICSI/ICMAI exam paper you were explicitly given as source. Claiming a real exam origin for a self-authored question misrepresents it to a student. |
| `year` | string | The current syllabus edition year given to you (e.g. `"2026"`). |
| `set` | null | Always `null` for generated practice content. |
| `qno_text` | null | Always `null` for generated practice content. |
| `marks` | integer | `1` for a standard MCQ, unless told otherwise. |
| `difficulty` | string | Exactly one of `"Easy"`, `"Medium"`, `"Hard"` — your genuine assessment, never a placeholder default repeated on every record. |
| `qtype` | string | Exactly `"direct-mcq"` unless the question shares a case/scenario with others, in which case `"case-mcq"` (see §5). |
| `case_ref` | string/null | `null` unless `qtype` is `"case-mcq"` — see §5. |
| `case_facts_html` | string/null | `null` unless `qtype` is `"case-mcq"` — see §5. |
| `question_html` | string | The question stem wrapped in `<p>...</p>`. Plain HTML only — see §4 for what's banned inside it. |
| `options` | object | **Always a lettered dict**, e.g. `{"A": "...", "B": "...", "C": "...", "D": "..."}`. Never a plain array/list. Use exactly the number of real options the question has — do not pad or invent options to force exactly 4. |
| `correct_option` | string | **Must be one of the exact keys in this record's own `options`** (e.g. `"B"`). Never the option's text, never a 0-indexed number, never `"1"`/`"2"`. |
| `answer_html` | string | `<p><strong>Answer:</strong> (X) {option text}.</p>` followed by `<p>{explanation}</p>` if you have one. The letter X must match `correct_option` exactly. |
| `chapter_slug` | string | Lowercase, hyphenated slug of the REAL unit/chapter name from the reference list you were given — e.g. `"law-of-demand-and-elasticity-of-demand"`. Compute this yourself from the reference list's real name; never copy a slug from an example or from a different chapter. |
| `chapter_label` | string | `"Chapt {chapter_no}"` — the chapter number from the reference list. |
| `unitcode` | string | `"Unit {unit_no}"` — the unit number from the reference list. If the chapter has no real sub-units (the reference list shows only unit 0/one row for that chapter), omit sub-unit numbering and just note it covers the whole chapter. |
| `topic_text` | string | A short, specific topic label for this exact question (e.g. `"Cross elasticity of demand"`), not just a repeat of the chapter/unit name. |
| `source_kind` | string | `"Study Material"` if based on the ICAI/ICSI/ICMAI study material PDF you were given. |
| `faculty_id` | null | Leave `null` — assigned later by the platform team, never invented by you. |
| `faculty_name` | null | Leave `null` — same reason. |
| `source_file` | string | The filename of the PDF you were given. |
| `source_document_hash` | null | Leave `null` — computed later by the platform team. |
| `publication_status` | string | `"Published"`. |
| `validation_status` | string | `"Verified"` if you are confident in the answer; `"Needs Review"` if you are genuinely unsure of the correct answer (see §6) — never mark something "Verified" you aren't sure about. |
| `generation_source` | string | `"Self-authored practice MCQ, based on ICAI Study Material"` (adjust "ICAI" to "ICSI"/"ICMAI" per course) — do not omit this field. |

### 3. Worked example (a complete, valid record)

```json
{
  "mcq_id": "CA-FND-ECO-CH2-U1-Q001",
  "course": "CA",
  "level": "Foundation",
  "exam_type": "PRACTICE",
  "year": "2026",
  "set": null,
  "qno_text": null,
  "marks": 1,
  "difficulty": "Medium",
  "qtype": "direct-mcq",
  "case_ref": null,
  "case_facts_html": null,
  "question_html": "<p>A buyer's demand schedule for ice-cream shows that at Rs 60 per cup, 0 cups are demanded; at Rs 50, 2 cups; and at Rs 40, 4 cups. What is the arc price elasticity of demand between Rs 50 and Rs 40?</p>",
  "options": {
    "A": "1.00",
    "B": "2.25",
    "C": "3.00",
    "D": "1.50"
  },
  "correct_option": "C",
  "answer_html": "<p><strong>Answer:</strong> (C) 3.00.</p><p>Using the arc elasticity formula: Ep = [(Q2-Q1)/(Q2+Q1)] x [(P2+P1)/(P2-P1)]. Here Q1=2, Q2=4, P1=50, P2=40. Ep = (2/6) x (90/-10) = -3. Taking absolute magnitude, Ep = 3.00.</p>",
  "chapter_slug": "law-of-demand-and-elasticity-of-demand",
  "chapter_label": "Chapt 2",
  "unitcode": "Unit 1",
  "topic_text": "Arc price elasticity of demand",
  "source_kind": "Study Material",
  "faculty_id": null,
  "faculty_name": null,
  "source_file": "CAFoundation-Eco-May26_M1-C2-U1_LawOfDemandAndElasticityOfDemand.pdf",
  "source_document_hash": null,
  "publication_status": "Published",
  "validation_status": "Verified",
  "generation_source": "Self-authored practice MCQ, based on ICAI Study Material"
}
```

### 4. JSON validity rules — never break these

- Output **only** the JSON array. No markdown code fences, no commentary before or after,
  no explanation — just the raw JSON, starting with `[` and ending with `]`.
- **Never write raw LaTeX/math syntax into a string** (no `$...$`, no `\%`, no `\frac{}{}`,
  no bare backslashes at all). Write numbers and formulas in plain text or simple HTML:
  "25%" not `25\%`; "1/4" not `\frac{1}{4}`. A real batch had exactly this defect — a
  stray `\%` inside a question string made the entire file unparseable JSON.
  - If you genuinely need a backslash character in text for some other reason, it must be
    written as `\\` (two characters) inside the JSON string, never a single `\`.
- Use `₹` (the actual rupee character) or the word "Rs" for currency — never a raw
  backslash-escaped symbol.
- Every string must be valid UTF-8. No control characters, no NUL bytes.
- Double-check every opening `{`/`[` has a matching closing `}`/`]`, every property has a
  comma except the last one in its object, and every string is properly quoted with `"`
  (not smart/curly quotes).
- Mentally re-parse your own output as JSON before returning it. If you cannot construct a
  valid parse tree in your head, something is wrong — fix it before responding.

### 5. Case-based (shared scenario) MCQs

If several questions genuinely share one case/scenario/narrative:
- Give them all the same `case_ref` (a short shared ID you invent, e.g. `"CS-1"`).
- Put the shared narrative in `case_facts_html` on **every** question in that group
  (repeated identically each time — the bot renders each question independently and needs
  the facts available on the record itself, not only on the first one).
- Set `qtype` to `"case-mcq"` for all of them.
- If a question stands alone, `case_ref` and `case_facts_html` are both `null` and `qtype`
  is `"direct-mcq"`.

### 6. Content fidelity — never guess silently

- Base every question strictly on the source PDF's actual content. Do not introduce facts,
  figures, or provisions the source doesn't state.
- If you are asked to write a numeric/legal/accounting question and are not fully certain
  of the correct answer, set `validation_status` to `"Needs Review"` rather than picking a
  plausible-looking option and marking it `"Verified"`. A wrong answer marked "Verified" is
  worse than an honestly-flagged one.
- Do not silently "correct" what looks like an error or an outdated figure in the source
  PDF — write the question faithfully to the source and note the concern in `topic_text`
  or leave `validation_status` as `"Needs Review"`, don't just change the number.

### 7. Self-check before you respond

Before returning your output, verify, one by one:

1. Root is a JSON array, nothing wrapping it.
2. Every object has the exact same keys as the worked example in §3 — no more, no fewer,
   no renamed fields.
3. Every `mcq_id` in the file is unique.
4. Every `chapter_label`/`unitcode`/`chapter_slug` traces back to a real row in the
   reference chapter list you were given — none invented, none copied from an unrelated
   example.
5. Every `correct_option` value is a literal key that exists in that same record's own
   `options` object.
6. No backslash appears anywhere except as a valid JSON escape (`\"`, `\\`, `\n`, etc.) —
   search your own output for a lone `\` before responding.
7. `exam_type` is `"PRACTICE"` on every record, unless you were explicitly given a real
   past exam paper as source (in which case say so and use `"MTP"`/`"RTP"`/`"PYQ"` instead,
   and set `source_kind` accordingly).
8. You could paste this into a JSON validator right now and it would pass with zero errors.

If any of the 8 checks fail, fix the output and re-check — do not deliver a file you
haven't verified against this list.

## For the operator (Pranav / whoever runs this)

- After receiving a completed batch back from an AI model, it still needs to go through
  `telegram/tools/ingest_ca_foundation_accounting_economics_mcqs.py`-style ingestion
  (or a new script following that same pattern for a different subject) before it's
  trusted live — that script's own preflight (duplicate IDs, `correct_option` validity,
  chapter/unit cross-check against `course_catalog`) is the real safety net, this prompt
  just makes far fewer of its checks fire in the first place.
- If a batch comes back with `validation_status: "Needs Review"` on any records, review
  those specifically before publishing — don't silently keep them live as "Verified" or
  silently drop them either.
- Regenerate `mcq_input_example.json`/`question_input_formats.pdf`/`.xlsx` in this same
  folder (`python telegram/base_formats/generate_base_formats.py`) if the production
  schema ever changes, and update this file's §2 table to match — keep the two in sync,
  they describe the same contract from two different angles (human-readable field sheet
  vs. AI-executable prompt).
