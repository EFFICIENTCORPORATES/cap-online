# 1Lavya Study Hub Bot — README

**Display Name:** 1Lavya Study Hub
**Bot Username:** @Official1LavyaStudyBot
**Script file:** `study_hub_bot.py`

## What this bot is for

A free, public Telegram bot that lets any student instantly pull study
material (PDFs) for **CA, CS, and CMA** — without visiting an app or
website. The student either taps through a guided menu, or just types
what they need directly, and the bot sends back the matching PDF.

Covers three material **categories**, per course:
- **Study Materials** — chapter-wise PDFs (1,026 files: 380 CA + 646 CS/CMA)
- **Exam Materials** — MTP/PYQ/RTP papers, currently only for CA Inter
  Advanced Accounting (58 files); more subjects can be added the same way
- **Revision Material** — not populated yet; the bot already handles this
  category gracefully (shows "not available yet" instead of an empty menu)

## How a student uses it

1. Student opens the bot and sends `/start`
2. They can either:
   - Tap **Browse** → pick **Category** (Study / Exam / Revision) →
     **Course** (CA / CS / CMA) → **Level** → **Subject** → **Chapter**
     (Study/Revision) or **Paper Type → file** (Exam), and the bot sends
     that PDF, OR
   - Just type what they want directly, e.g. `CA Inter cash flow`,
     `CS company law`, or `MTP Jan 2025` — the bot fuzzy-matches this
     against the *entire* catalog (all categories, all three courses) and
     sends the file (or shows up to 8 closest matches to pick from if
     unsure, labelled with Category/Course/Level/Subject so same-titled
     results across courses/levels are distinguishable)

## How the backend works — catalog is generated, not hand-maintained

- The bot runs as a **Python script on a laptop** (not a cloud server) —
  the laptop must stay powered on and the script running for the bot to
  respond. If it's closed, the bot goes offline.
- All files live under `telegram/assets/study_bot/`, one flat folder per
  category: `Study Materials/`, `Exam Materials/`, `Revision Material/`.
- **One master Excel catalog** —
  `telegram/source-docs/StudyHub_Master_Catalog.xlsx` (`Catalog` sheet) —
  is what the bot actually reads at startup. It is generated by
  `telegram/tools/build_master_catalog.py`, which merges three sources:
  - `1Lavya_Study_Hub_File_Mapping.xlsx` (CA study chapters — built by
    `build_study_bot_catalog.py`)
  - `CS_CMA_Chapter_Catalog.xlsx` (CS/CMA study chapters — built by
    `build_cs_cma_catalog.py` + `split_cs_cma_pdfs.py`)
  - `Exam Materials/`'s own filenames, parsed directly (they already
    encode Course-Level-Subject-PaperType-Session-Set-DocType)
- **Never hand-edit the master Excel or move files around inside
  `telegram/assets/study_bot/`** — fix the upstream source (the CA/CS/CMA
  catalogs, or the Exam Materials filenames) and re-run
  `build_master_catalog.py`. It cross-checks itself against disk every
  run (every catalog row must have a matching file, and vice versa) and
  fails loudly, not silently, if anything drifts.
- Full pipeline detail is in `_claude/skills/SKILL-study-bot-catalog-pipeline.md`,
  `SKILL-cs-cma-toc-pipeline.md`, and `CLAUDE.md` §10 — read those before
  touching anything in this area.
- Free-text search uses fuzzy matching (`rapidfuzz`) against every
  descriptive column at once (Label, Subject, Course, Level, Keywords,
  PaperType, Session, ChapterNo) — one search covers all three courses
  and all three categories simultaneously.

## Setup checklist for the developer

1. `pip install python-telegram-bot rapidfuzz openpyxl pandas`
2. Get the bot's API token from **@BotFather** on Telegram (already
   registered as `@Official1LavyaStudyBot`)
3. Put the token in `telegram/creds.txt` under a
   `Name: Official1LavyaStudyBot` / `Bot Token: ...` block (this file is
   gitignored — never committed), or set the
   `TELEGRAM_STUDY_BOT_TOKEN` environment variable (takes priority if
   both are set).
4. `EXCEL_PATH` and `STUDY_BOT_ROOT` are resolved automatically,
   repo-relative — no path editing needed as long as you run the script
   from inside a `cap-online` clone.
5. If the material changes (new subject, new session's exam papers,
   Revision Material gets populated), re-run
   `python telegram/tools/build_master_catalog.py` (after re-running
   whichever upstream catalog script produced the change), then restart
   the bot.
6. Run: `python telegram/bots/study_hub_bot.py`
7. Test `/start`, the full Browse flow for at least one subject in each
   of CA/CS/CMA, the Exam Materials path, and free-text search.

## Things to watch out for

- **Don't hand-edit the master Excel or rename/move files under
  `telegram/assets/study_bot/`** — everything is regenerated wholesale by
  `build_master_catalog.py` every time it runs. Fix things upstream and
  re-run it; it will tell you exactly what's out of sync if anything is.
- Every piece of `callback_data` in the bot's inline buttons must stay
  under Telegram's hard **64-byte limit** — this has bitten the bot twice
  already (see `SKILL-study-bot-catalog-pipeline.md` §6). The fix in
  place: every variable-length value (Subject, PaperType selection, file)
  is passed as a small integer **index or row id**, never as the literal
  string, resolved back through the catalog. If you add a new browse
  level, follow the same pattern — never put a raw Subject/Label string
  into `callback_data`.
- `FUZZY_MATCH_THRESHOLD` / `TOP_N_SUGGESTIONS` (top of the script)
  control how loose free-text matching is and how many results show —
  tune after real-world testing.
- Some chapters legitimately appear under **more than one subject's
  catalog**, and now also potentially across categories, because the
  source material itself repeats topics (e.g. Cash Flow Statement is
  both its own AS-3/AS-7 chapter in Study Materials AND the subject of
  MTP/PYQ questions in Exam Materials) — this is correct, not a
  duplicate-tagging bug.
- No payment/premium gating yet — this bot is fully free. If premium
  tiers get added later, they'll need a `user_id → plan` mapping and
  gating logic added to this script.
