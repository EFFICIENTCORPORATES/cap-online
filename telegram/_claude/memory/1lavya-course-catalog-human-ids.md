Built 2026-08-11. Pranav's ask: consolidate the platform's Course→Level→Subject→Chapter→Unit taxonomy into one DB table as the single source of truth (not independently-typed tags on each question), and give every question an additive human-readable ID (`CA_L2_P01_C3_U4_00876` format) alongside its existing internal ID, retrofitted onto all existing content.

**Investigated first**: found 4 different, mutually inconsistent MCQ ID schemes already in production. But also found real, already-verified raw material (not needing fresh research): `books/concept-book/syllabus-engine/data/1-ca-inter-adv-accounts-topic-page-index.json` (canonical CA Inter Adv Accounting), `telegram/source-docs/CS_CMA_Chapter_Catalog.xlsx`'s Chapter Catalog sheet (647 real CS/CMA chapters w/ PaperNo, read off real ToCs), `telegram/tools/cs_cma_common.py`/`build_study_bot_catalog.py` (paper numbers, verified against real cover pages in an earlier session), `StudyHub_Master_Catalog.xlsx` (CA Foundation Quant Aptitude's 18 chapters).

**Locked decisions** (AskUserQuestion, since this touches every question's identity): course code is **CMA not CO** (matches everything else in the platform); CS levels map **CSEET=L1, Executive=L2, Professional=L3**; paper numbers **re-verified** against already-trusted sources (not re-typed); human_id is **additive** (never replaces mcq_id/book_id); **retrofit all ~2,500 existing questions now**, deterministically, catalog-driven.

New `course_catalog` DB table (701 rows) + `telegram/tools/populate_course_catalog.py` (full-rebuild, 3 sources) + `telegram/tools/generate_mcq_human_ids.py` (catalog-is-authoritative retrofit, idempotent — a real mismatch found: CA Foundation Quant Aptitude's MCQs self-tag U1 but the real material has no sub-units, catalog's U0 used instead). 2,486 questions across 6 files now have `human_id`. New Admin Portal → Content → Course Catalog page. `smoke_test_course_catalog.py` (39 checks, including a real second-run idempotency proof) + admin portal smoke test grew to 72.

Also fixed same session: the "year" Content Health warning (`--year` never passed converting Arun's CMA Foundation Law docx — fixed at source, re-merged).

See [[1lavya-admin-portal-foundation]], [[1lavya-csarunchouhan-demo-content]]. Full detail: `telegram/COURSE-CATALOG.md`.

**Why:** prevents chapter/unit tagging from silently drifting between content files and the real syllabus; gives students a citable, permanent reference ID for any question.
**How to apply:** any NEW subject's question content needs its chapter/unit numbers added to `populate_course_catalog.py` from a real verified source FIRST, then `generate_mcq_human_ids.py` needs a new `CONTENT_SOURCES` entry (with its own resolver if the tagging format is novel) before it can get human_ids. Never hand-type a human_id — always regenerate via the script so the catalog stays authoritative.
